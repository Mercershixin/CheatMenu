## 二、逐条裁决表（AGENTS §7 口径）

### ✅ 真：已落地（本轮改的三件）

| # | 技法 | 出处 | 为什么现有实现不够 | 落地形态 |
|---|---|---|---|---|
| **P1** | **双投递 + 相机写入存活率探测 + 鼠标灵敏度自学习** | `universal.lua` 的 `deliverMode()` / `aimPass()` | 现有 `aimTick` **只写 `cam.CFrame`**。而大量游戏每帧从自己内部角度重建相机 ⇒ 写入下一帧被丢，表现是**「自瞄看着在动、其实没生效」** | 新模块 `SYS.UA`：`UA.Deliver()` 接管投递；相机存活率<50% 且执行器有 `mousemoverel` → 自动改走鼠标；灵敏度用「上一帧请求 vs 本帧实际」EMA 学习（0.85/0.15），**亚像素请求跳过**（否则从"没发生的移动"里学习） |
| **P2** | **游戏自带瞄准命中盒优先** | `universal.lua` 的 `resolveParts()` / `looksLikeHeadHitbox()` | 现有 `CB_PART_ORDER` 只有写死的 Roblox 名字。而 DoW 的 `AutoAimAreaHead/Body`、Counter Blox 的 `HeadHB` **才是游戏自己打的目标** | 新开关 `CB_HitboxFirst`（默认开）：`UA.GameHitbox()` 先按名字特征找自带命中盒，**有就用、没有完全按老名单走**（行为不变） |
| **P3** | **执行器能力实测** | `phantomforces.lua` §executor capabilities | `游戏信息 / 执行器能力` 扫描器原来是**空壳**（`return {"（见头部）"}`） | 换成真探测：`mousemoverel` / `Drawing` / `hookfunction` / `getconnections` / `getgenv` / `mouse1click` / `keypress` / VirtualInputManager / `setfpscap`，并给**结论行**（"重建相机的服也能自瞄" / "只能写相机"） |

**配套（都来自 phantomforces 的工程笔记，逐条都有实测出处）：**

- ★★ **取执行器全局绝不用 `rawget(getfenv(),"mousemoverel")`** —— Potassium 类执行器通过 env 的
  `__index` 交付全局，`rawget` 拿到 nil ⇒ 静默退化成相机路径。**原版 `universal.lua` 就栽在这，
  白丢了整个自瞄**（原文实测：误差 10.30° 收敛到 2.62° 又回到 8.62°）。本项目 `GENV`/`G()` 本来就
  是 `pcall(getgenv)` / `pcall(game:GetService)`，这条**本来就是对的**，本轮只把它写进新模块的注释与文档。
- **人类化用「平滑随机游走」而不是每帧白噪声** —— 白噪声在相机上读起来是**抖**，游走读起来是**手**
  （原文注释原话）。落地为 `UA_Human`：反应延迟 + 每秒角度上限 + 死区 + 6 Hz 游走。
- **`hookfunction` 没有撤销**（原文 §10）—— 重复 hook 会**叠加**。本项目 `_audit_hygiene` 的
  "每处安装都有对应还原路径" 就是这条纪律，**继续保留**。
- **服务名随机 ⇒ 永不 `game.X`，一律 `game:GetService`**（原文 §1：`game.Players` 直接 throw）。
  本项目 29 处 `game:GetService` / **0 处 `game.X`** —— 早已符合，无需改动。

### ❌ 不成立 / 不该抄（红线与既有裁决）

| 技法 | 为什么不抄 |
|---|---|
| `hookmetamethod(game,"__index")` + `"__namecall"` 全局劫持（Open-Aimbot 双劫持） | `AGENTS §1` 第 3 条：总入口 hook 是**所有实例方法调用的入口**，实测就是卡顿掉帧的病根。项目保留的唯一一处 `__namecall` 是**单点射线改写**（静默瞄准/穿墙），不扩 |
| 把 `Drawing` 当默认透视 | **用户已裁决**（12.1.0 那次调研就写了）：「位置正确 > 反检测收益，容器/表现不动」。本轮**不动** |
| webhook 上报（`anticheat_bypass.lua` 的 `WEBHOOK_URL`） | 把玩家数据发到**别人的服务器**。**绝不要** |
| hook `print`/`warn`/`error` 灭日志（`Ult-Killer.lua`） | 把自己的「错误显形」也一起灭了 —— 与本项目 V3「静默的假功能比没功能更坏」直接冲突 |
| 删 `getgenv()` 执行器全局 / 改环境元表 `__index` 返回 nil | 删全局 = 自己也没得用；改元表 = 红线 |
| 给自建实例起随机名（DarkHUB 那招） | **12.1.0 已登记为可借鉴**，但需真机验证才动 —— 不在本轮范围 |
| `SetNetworkOwner` 抢所有权 | SA 下直接报错，且 2026-07-09 起 SA 已正式发布 |

### ⏭ 属新增功能但**本轮不做**（要用户点头）

- Open-Aimbot 的 **SpinBot**（转圈）与**随机命中部位**：会改变玩家可见行为，且与"更像人"目标相反。
- `AutoAimArea*` 之外还要**枚举所有 BasePart 算朝向**（某些游戏命中盒没名字）：成本高、收益不确定。
- 断 `getconnections` 掐游戏自己的属性监听：本机执行器（Real）没有 `getconnections`（实测），
  这条**在本机走不了**；扫描器会如实报 ❌。

## 三、★★ 必须说清的边界（本轮没有、也不会写假功能）

| 用户点名的 | 能不能"全服通用" | 为什么 |
|---|---|---|
| **透视 / 高亮** | ✅ 本来就通用 | 纯本地表现层，不依赖服务端 |
| **自瞄** | ✅ **本轮之后显著更通用** | 补上了"重建相机的服"这条最常踩的坑；**但**服务端记录视角角度的游戏（实测 BloxStrike 128 Hz）事后仍可算出异常 —— 安全的**只有运动形态**（反应延迟/角度上限/死区/游走） |
| **飞行 / 加速 / 传送** | ❌ 服务端权威(SA)服**无解** | 引擎直接拒绝客户端写入。`Workspace.AuthorityMode = Server` 即当场结案（扫描器会报） |
| **真无敌 / 锁血** | ❌ 做不到 | 伤害与血量在服务端结算；调研到的两个主流 hub **也都没有**实现 |
| **绕反作弊** | ⚠ 只能到第 ④ 层 | 中性名/少留特征实例只**降低被抓概率**；对「动态注入式」反作弊，唯一活路是**上报数值自洽**（别伪造） |

一句话：**能通用的是「本地表现 + 输入路径」，不能通用的是「服务端结算的东西」。**

## 五、★ 门禁当场逮到的一个真 bug（构建过程，记录下来）

第一版构建出来 `verify_all` **12/13**，红在第 7 步 `check_globals.py`：

```
CheatMenu-12.2.0.lua   未知全局 55 种   !! 白名单之外的新名字: CB
```

原因：新写的「执行器能力实测」扫描器在**第 ~4700 行**，而 `local CB=SYS.Combat` 在**第 8435 行** ——
扫描器里直接写了 `CB.TeamKeyUseful()`，于是成了**「在 local 声明之前引用它」**。
这正是 `check_globals` 说明里点名的 bug 类型（UI.Defs 那次就是同款）。

修法：扫描器改走 `SYS.Combat`（`SYS` 是早声明的作用域根，且扫描器是**运行期**才执行）。
⇒ **新增"给扫描器/UI 段写代码"时，凡是被引用的模块表，先确认它的 `local` 声明在文件里更靠前**；
不确定就一律走 `SYS.X`。

> 记这一笔是因为它证明门禁**真在干活**：静态编译（`luau-compile` 双模式 exit 0）完全看不到这个问题，
> 只有"词法作用域"那一关会逮。
