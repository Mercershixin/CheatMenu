## 三、结论：迭代代码 / 重复补丁 —— 硬问题只有 **2 处**，都已修

### ① 硬问题（已修）

**🔴 P1 —— 一枚「无效补丁」：迁移条件自相矛盾，从未生效过**

```lua
-- 12.1.4（旧）
if (SYS.C_.CB_FireDelay or 0.08)==0.06 then SYS.C_.CB_FireDelay=0.08 end
--                        ^^^^^^ 兜底值 0.08        ^^^^^^ 比较值 0.06
```
`X` 为 `nil`（老存档从没设过这条）时兜底成 **0.08**，**永远等不到 0.06** ⇒ 分支恒假 ⇒ **这一行从写下那天起就没执行过**。
本意显然是「只把**等于旧默认 0.06** 的升到 0.08，用户手调过的一律不动」——**旁证**：同文件读这条时的兜底正是 `0.06`。
```lua
-- 12.1.5（新）
if (SYS.C_.CB_FireDelay or 0.06)==0.06 then SYS.C_.CB_FireDelay=0.08 end
```
（同段的另外三条 `CB_SnapMaxAngle` / `CB_SnapMinGap` / `CB_SnapDelay` 兜底与比较值**都自洽**，只有这条错 ⇒ 说明是当年的手误，不是设计。）

**🧹 P2 —— 历史名残留（真·迭代痕迹）：`CreateMenuLegacy`**
全项目**只有一个**菜单实现，但它的名字叫 `Legacy`，而 `CreateMenu()` 只是一层
`return CreateMenuLegacy()` 的空壳。当年大概做过"新版菜单"、后来回退到旧版，**名字没改回来** ⇒
后来者会以为"还有个新版菜单在别处"。已**正名**为 `CreateMenu` 并删掉那层空 wrapper。

### ② 逐类核过、**确认干净**的（不是没查，是查完没动）

| 判据 | 结果 | 说明 |
|---|---|---|
| **成员级重定义**（`SYS.X`/`UI.X`/`CB.X` 被定义两次） | **0** ✅ | 真·补丁摞补丁的判据；本仓**没有** |
| 裸名同名（`scan`/`refresh`/`add`… 各 2~4 处） | 13 个，**全合法** | 不同作用域的同名**局部函数**（Lua 里各自独立），不是覆盖 |
| **默认值表内串键**（同一 `T_`/`C_` 键赋两次） | **0** ✅ | |
| 迁移块（6 处） | 全部**有意义** | 只在"老存档里确实有旧键"时才动，是防老存档的正规手段；且**没有一处**检查"已不存在的键" |
