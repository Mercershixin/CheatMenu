# 移动反作弊能不能绕？—— 公开技法调研 + 本项目红线裁决

> 2026-09-24。起因：用户「移动反作弊能绕吗 或者欺骗之类的，看看别人 git 的仓库是怎么做的，学习一下」。

## 一、先说结论（一句）
**「能不能绕」取决于该服的 `Workspace.AuthorityMode`，不取决于技法。**
⇒ **先测 SA，再谈技法** —— 这就是为什么我在「🧪 移动自检」里加了这一行。

## 二、关键事实：Server Authority 已于 **2026-07-09 正式发布**（opt-in）
- 开启方式：Studio → `Workspace` 属性 → `AuthorityMode = Server`（会自动带上 5 个前置：NextGenerationReplication /
  PlayerScriptsUseInputActionSystem / SignalBehavior=Deferred / StreamingEnabled / UseFixedSimulation）。
- 开启后 **服务端是唯一事实来源**：客户端只发**输入**，由服务端模拟；客户端只做**预测 + 回滚**。
- ⇒ **引擎层直接拒绝**：速度篡改、飞行、穿墙、瞬移、属性篡改。作弊者的客户端可能短暂显示幻影，但**服务端会把他拉回，别人永远看不到**。
- ⇒ ★★ **且 `SetNetworkOwner` 在 SA 下会直接报错**（服务端永远是 owner）—— 也就是说
  **"抢网络所有权"这条流传最广的老路，在 SA 下彻底死了。**

## 三、社区/公开仓库在这个问题上的做法，按"能不能用"分三类

| 类 | 典型做法 | 前提 | 对本项目 |
|---|---|---|---|
| **A. 改上行位置上报** | hook `RemoteEvent.FireServer`，改写/限速位置参数 | 必须**客户端权威**（无 SA）**且游戏存在位置上报通道** | ✅ 我们已有（`AntiRevert`）；但**这机制只对 TP 有意义**，见 §5 |
| **B. 抢网络所有权** | `part:SetNetworkOwner(player)` | 同上；**SA 下报错** | ⛔ 不适用 |
| **C. 让服务端"自己"动你** | 用游戏**合法机制**：冲刺/加速 buff、传送门、载具… | 游戏**确实提供**这类通道 | ⭐ **唯一在 SA 下仍可用的路** |
| D. 关/替换反作弊模块 | 删 `PlayerModule.ServerAuthorityClient` | 只影响**本地预测**，不改变服务端判定 | ⛔ 无效 |
| E. 蹭"宽限窗口" | 按 `AntiCheatMovementGraceUntil` 这类窗口错峰操作 | 需知道服务端判据 | ⚠ 只能降低被标记概率，**突破不了速度上限** |

## 四、本项目红线裁决（**哪些不能抄**）
- ⛔ **不抄** `hookmetamethod(game,"__namecall"/"__index")` 关键词搜索（AGENTS §1 第 3 条）。
- ⛔ **不抄**"伪造位置/伪造玩家状态发给服务端"（不做服务端伪造）。
- ⛔ **不新增** `getrawmetatable` / `setreadonly`。
- ✅ **可抄/已有**：单点 `hookfunction`、读属性做**诊断**、用游戏**合法机制**、把上报伪装做成**可调开关**。

## 五、★ 一个必须讲清的物理事实（也是 11.7.0 的设计依据）
「**跑得快**」与「**看起来正常**」**不可兼得**：
- 上报速度上限 **< 你的实际速度** ⇒ 服务端把你**拽回**（= 定在原地）；
- 上报速度上限 **≥ 你的实际速度** ⇒ **等于什么都没做**。
⇒ 所以 `AntiRevert` 默认开只做**一件事**：把**单帧大跳**（TP，几百格/帧）拆成连续位移
（阈值 `C_.RevertJump=150` 格/帧，而正常跑/飞每帧 ≤ ~10 格 ⇒ 零影响）。
**它不能把持续高速伪装掉 —— 那是物理不允许，不是参数没调好。**

## 六、对偷鱼（PlaceId 99183404085821）的净结论
- 该服特征与该模型**高度吻合**：`PlayerModule.ServerAuthority.*` 在位 · **零移动通道** · `AntiCheatMovementGraceUntil` 明确是**服务端在跟踪移动**。
- ⇒ **极可能是 SA 服**。**先点「🧪 移动自检」看 `AuthorityMode`：**
  - 若为 `Server` ⇒ **移动类客户端无解，当场结案**（引擎级拒绝）。
  - 若为 `Automatic` ⇒ 那只说明"飞不动"**另有原因**（游戏每帧改写速度 / 服务端回滚），再往下查。
- **唯一可走的是 C 类（用游戏自己的机制）**。偷鱼扫描里可用的候选（**全部属新增功能，必须先报清单、经你点头**）：
  - `ChaseFishSystem.ChaserSpeedOffer`（被追鱼时游戏主动给提速）
  - `DayNightSystem.OceanTeleportFade` / `OceanTeleportFadeReady`（游戏自带海上转场）
  - `TreadPool*` / `TankLevels.UpgradeTank`（水池 / 水缸）
  ⚠ 这三条都要**先做只读探针**（看参数签名）才敢动。

## 七、以后遇到"某服移动没用"的标准流程（照着走，别瞎试）
1. 点「🧪 移动自检」→ 读 **`Workspace.AuthorityMode`** + **角色网络所有权** + **实际速度**。
2. `AuthorityMode = Server` ⇒ **结案**（客户端无解），不要再花时间。
3. `Automatic` ⇒ 再看：游戏是否**每帧改写** `WalkSpeed`/速度（自检里有对比）· 是否被**服务端回滚**（速度好看但人被拽回）。
4. 只有在 1~3 都排查完，"本地驱动"仍无效时，才考虑换驱动方式（LinearVelocity → BodyVelocity → CFrame → WalkSpeed）。
