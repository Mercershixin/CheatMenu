## ★ 最重要的发现：B 层（游戏函数表）暴露了每个小游戏的脚本名 + 内部函数

`scan_127775478639865.txt` 的 B 层「按归属脚本分组」+「名字可疑的函数」两段里，**直接写出了**：

```
MachinePartyBlindout      → aimFromMouse · aimFromStick · faceAim
MachinePartyRightOfWay    → aimFromMouse · aimFromStick · drawAim · killMarkers
MachinePartyDuckHunt      → aimRifle · fire · markHit · pushAim · sampleAim
SpiderRig                 → AimHead · KillBodyOffset · PoseKill
BumperMadness / BumperMadnessUI
PadBuy                    → Claim
```

⇒ 三个直接推论：

1. **`RightOfWay` / `Blindout` 有 `drawAim`** —— "该按哪个方向"是**客户端自己画出来的**。
   客户端知道答案 ⇒ **本地能读到答案** ⇒ "提前知道哪个是对的"**成立**，不是碰运气。
2. 这两个游戏的输入函数是 **`aimFromMouse` / `aimFromStick`** —— 收的是**方向**（鼠标/摇杆向量），
   不是写死的某个键。WASD 与方向键都能喂进去。
3. **`SpiderRig` 的 `AimHead` / `PoseKill` / `KillBodyOffset`** —— 蜘蛛的"锁头 → 摆姿 → 扑杀"
   是一串**客户端脚本函数**，不是黑盒。这意味着躲蜘蛛可以从"靠近就退"升级成"**预判它要扑谁**"。

## 逐条

### 1. 地雷探测 / 透视地雷位置 —— **现在就能**

- 依据：`minefield` 在 `SYS.MiniArea`（源码 L3685-3688）；`SYS.KwHazard` 已含 `mine` / `bomb` /
  `landmine` / `地雷` / `炸弹`；小游戏区域内的机关会被"危险升级"标红。
- 用法：视觉页「物件透视」总闸（同时点亮小游戏区域）+ MachineParty 页「自动躲伤害机关」。
- 缺口：无。

### 2. 魔方全自动打好 —— **零线索**

- 我搜了 `cube / rubik / puzzle / tile / solution / correct / answer`，**这份扫描里全 0**。
- 但原理上一定可行：魔方是**有限状态 + 确定解法**，只要状态在客户端（朝向 / Value / 闭包 upvalue），
  就能读状态 → 算解法（层先法或 Thistlethwaite）→ 反向操作。
- 缺口：**魔方的状态存在哪**。需要它正在场时扫一次。

### 3. 武器零件：自动找 + 自动组装 —— **部分现在就能**

- 「自动组装 / 捡零件」= 触发型 ⇒ **`AutoHitMinigame` 已覆盖**：扫小游戏区域里所有
  `ProximityPrompt` / `ClickDetector` 自动触发。这份扫描里机器派对有 **185 个 ClickDetector + 7 个 ProximityPrompt**。
- 「找」= 物件透视（区域内的小游戏物件会高亮）。
- 缺口：零件/组装台的**命名是否落在小游戏区域判据内**。若不在，把它们的名字加进 `SYS.MiniArea` 即可（一行）。

### 4. 电梯玩法：按指示方向按 WASD，要全对 —— **补一次探测即可**

- 依据见上「最重要的发现」第 1、2 条：`drawAim` 在客户端画方向，`aimFromMouse/Stick` 收方向输入。
- 做法：读那条"指示" → 发出对应方向（`SYS.Keys` 已经有按住/连按能力，上轮加的）。
- 缺口：**那条指示对应的实例/字段** + 该游戏期望的 `KeyCode`。
- ★ **上轮已经给扫描器补好了 `InputBinding` / `InputAction` 路径** ⇒ **重扫一次就能拿到**。

### 5. 方块随机变、要踩对 —— **同第 4 条**

- 逻辑与第 4 条完全一样：只要"正确答案"由客户端决定（B 层的 `drawAim` 证明这类游戏答案就在客户端），
  就能**提前读出来**，再自动走/按对。
- 缺口：这个小游戏对应哪个脚本（B 层只列出了"名字可疑的 43 个"；全量函数分组在落盘文件里）。

### 6. 躲火车 —— **现在就能（可能只差一个词）**

- 依据：`trainrace` 在 `SYS.MiniArea`；`AutoDodge` 扫 `SYS.KwHazard` + 名字含「门/陷阱/机关/关卡/考验」
  的物件，15 格内自动**水平**退开（限速 ≈21 格/秒，不触发瞬移检测）。
- 缺口：火车物件名是否命中判据。**若没命中，把 `train` / `locomotive` 加进 `SYS.KwHazard` 就行**。

### 7. 躲蜘蛛 —— **有钩子，补一次探测**

- 依据：`SYS.KwHostile` 已含 `spider` ⇒ **怪物透视已经能标蜘蛛**，`AutoDodge` 也能躲。
- 更强的一条：`SpiderRig` 的 `AimHead` / `PoseKill` / `KillBodyOffset` 是客户端函数 ——
  可以用本项目已有的「按名字包一层（**只记录，不改返回值**）」去观察：
  它锁了谁、什么时候调用。拿到就能**预判扑击**而不只是"靠近就退"。
- 缺口：这三个函数的调用时机与参数。

### 8. 丢石头 —— **零线索**

- 搜 `rock / stone / throw`，全 0。
- 形态决定做法：若是"点一下丢"→ `AutoHitMinigame` 已覆盖；若是"蓄力/角度投掷"→ 属输入型，
  需要它的参数（初速/角度）才知道怎么自动算。
- 缺口：它是什么形态。需要它在场时扫。
