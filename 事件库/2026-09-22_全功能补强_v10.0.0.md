## 一、自动躲避：五项全部可调（原来只有一项勉强算可调，还没界面）

| 参数 | 原状 | 现在 |
|---|---|---|
| `DodgeDist` 触发距离 | 默认 15 格，**后端读但界面上没有任何入口** ⇒ 用户根本改不了 | 滑块 3~60 |
| `DodgeDepth` 扫描深度 | **写死两层**（Workspace 顶层 + 每个子对象的前 80 个） | 滑块 1~4 层 |
| `DodgeCap` 每层上限 | 写死 80 | 滑块 20~400 |
| `DodgeScanSec` 重扫间隔 | **写死 2 秒** | 滑块 0.2~3 秒 |
| `DodgeStep` 退避速度 | **写死 0.35 格/帧**（≈21 格/秒） | 滑块 0.10~1.20 |

**为什么这五项重要**（每一项都对应一个"会让人以为功能坏了"的现象）：

- **扫描深度**：原来固定两层 ⇒ **藏在 Model 更深处的机关扫不到**。机器派对不少机关是嵌套几层的。
  现在改成**可配深度的 BFS**，能扫到 3~4 层。
- **重扫间隔**：原来固定 2 秒 ⇒ 新出现的机关最多 2 秒后才被认识 —— 快速机关就是在这 2 秒里撞上的。
  （列表里已有的物件本来就每帧读实时位置，所以移动的机关一直能跟住；这里管的是"多久重新找一遍"。）
- **退避速度**：原来固定 0.35 格/帧。上限卡在 **1.2 格/帧（≈72 格/秒）** ——
  再快不属于"更快地躲"，而是**瞬移位移**，会被服务端按异常处理。

> 源码位置：`AutoDodgeScan`（BFS 深度可配）/ `AutoDodgeTick`（周期与退避速度可配）；
> 5 个参数都已在 `SYS.C_` 声明（不声明就存不住 —— 这个坑 `CB_ScanMs` 踩过）。

## 二、扫描深度 / 完整性补强（用户：「扫描的深度补强一下」）

| 项 | 原状 | 现在 |
|---|---|---|
| **躲避扫描深度** | 滑块上限 4 层 | **1~8 层** |
| **数据层时间预算** | 写死 0.6 秒 | **1.5 秒** |
| **值对象层时间预算** | 写死 0.6 秒 | **1.5 秒** |
| I 层「每类收集条数」 | 40 | **200** |
| B 层「脚本分组控制台显示」 | 25 组 | **60 组** |
| 射线改写候选 / 后坐力候选 | 24 个 | **40 个** |
| 绿色物件控制台显示 | 60 条 | **200 条** |
| 小游戏脚本函数显示 | 30 个 | **60 个** |

**关键说明**：

- **深度为什么放到 8**：机器派对的机关有的嵌在「关卡 Model → 组件 Model → 零件 Model」这种三四层里，
  4 层刚好卡在边界上。**但深度每 +1 层成本翻几倍** —— 配套的「每层上限」才是刹车：
  **真遇到大图优先调小「每层上限」，不要降深度**（降了就整层漏扫）。
- **两处 0.6 秒预算**：0.6s 在值对象多的大图上**是会**触发的，一截断数据就不全。
  1.5s 是给大图留的余量 —— 这段是**同步跑**的，再往上就是白卡界面。
  截断提示也一并改成「碰 1.5s 上限」+「可再跑一次，通常第二次更快」。
- **发现类上限**只决定"一次能看到多少" ——**落盘文件本来就是全量**。

### ⛔ 明确**没有**放宽的（放开是自伤，不是补强）

| 项 | 为什么不动 |
|---|---|
| `maxNums=90`（数值槽上限） | 这是**写回游戏**的上限。放开 = 往游戏里写几百个 upvalue，会把武器逻辑改烂 |
| Gun 扫描 8 秒预算 | 放开 = 扫描线程占更久，界面更卡 |
| `TRAP_MAXSTEP` | 放开 = 被服务端按 Illegal Teleport 踢 |
| pcall / 错误自停 | 放开 = 崩 |

## 三、综合扫描新增：小游戏区域内的绿色物件清单

**为什么要**：你描述的火车玩法是「进绿灯位置就安全、过后要出来，不然被压死」——
**整个自动化的关键就是找到那个绿点**。而现有透视**只按名字分类**，
而"绿灯 / 安全格"这种东西很可能是靠**颜色**表示的（绿色 Part / Neon 材质），**按名字永远搜不到**。

- 判定刻意收紧：绿要明显高于红和蓝（`g>0.35 且 g>r*1.35 且 g>b*1.35`），避免灰/白/黄的物件被误收。
- **只读、只列**，不改任何东西。
- ★ 性能：**只遍历小游戏区域根对象的后代**，不遍历全图（9 万实例）—— 快两个数量级。
- 输出里每张图会报「绿色物件 N 个」；一个都没有时会说明"绿灯可能不是靠颜色表示的"，并给下一步排查方向。

## 四、按键自动化：支持一次按多个键

- 键名可以用 `+` 组合：`W+D`（斜向）、`Up+Left` 等。UI 选项扩到 16 个（含 8 个组合）。
- 解析失败（键名写错）时**什么都不按**，不会乱按。
- 切换键时会把**不在本次名单里**的旧键先松开，不会同时按住两个方向。
- 关闭开关时照旧 `ReleaseAll()`（绝不把键留在按住状态）。

## 五、明确说明：躲避**治不了**「进绿灯安全点躲火车」

`AutoDodge` 只会「**沿直线远离**危险物」。而那个玩法的正解是
「**按信号进/出固定安全点**」—— 这是**时序**问题、不是"闪避"问题：

| | 需要什么 |
|---|---|
| 躲地雷 / 静止机关 | ✅ 现有躲避**对症**（位置固定、离远了就安全） |
| 进绿灯躲火车 | ⚠️ **不对症**。需要先知道：① 绿灯位置在哪 ② 信号怎么读（灯亮/灭，还是火车位置） |

新加的「绿色物件探测」就是为拿这个证据铺的路 —— **在那张图在场时重扫一次**，绿点在哪就一目了然。
