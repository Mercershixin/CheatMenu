## 🔧 一、补强清单（六条，全部有本次实锤）

### ① ★★ `SYS.Gun` 的 GC 扫描在**这台会被截断**（最高优先级）

**实锤**：这台 **函数 130100 个**，而 `SYS.Gun` 的扫描是 **上限 40000 函数 + 6 秒预算**
（两天前按机器派对 2.1 万函数的规模定的）⇒ **武器逻辑大概率根本扫不到**，
表现就是"开关是开的、一个都没挂上"。

**修法（两条一起，缺一不可）**

1. **用「归属脚本」把范围收窄** —— B 层已经证明：**即使拿不到 `debug.info` 的 source，
   仍然能按脚本名分组**（`CanShoot` → 脚本=`CommonShootableComponent`）。把这套归属能力
   用进 `SYS.Gun`，只扫**武器 / 命中 / 瞄准 / 弹药相关脚本**的函数 ⇒ 从 13 万降到几百个，
   **既不截断又精确**。
2. **只扫"有名字"的函数** —— 归属显示 `-` 的是匿名函数/引擎侧（B 层原话："拿不到 = hook 不了"），
   本来就不该动。

> 这条不修，射击增强那 6 个开关在这款游戏上基本是**装饰**。

### ② `ADMIN` 词表里 `ban` 过宽 → **把游戏玩法通道误标成处罚通道**

**实锤**：`GameService.RoomManager.Room.BanMap` 与 `.ShowBanMap`（**地图禁用玩法**）
被判成「⛔ 管理后台/处罚通道 —— 触发=自报家门」（`ADMIN` 含裸 token `"ban"`，`BanMap` 拆词后命中）。

**影响面（已核对，别慌）**：只影响**报告标签** —— 自动藏身/自动小游戏用的 `SYS.IsHoneypot()`
读的是 `HONEY` + `PHRASE_HONEY`，**不含 ADMIN** ⇒ **不会被误挡**。

**修法**：把 `ban`（以及同样过宽的 `report`）从裸 token 表挪到**词组表**
（只认 `ban_player` / `banuser` / `report_player` 这类真处罚通道），或加排除表
`banmap` / `showbanmap` / `votemap`。

### ③ 穿墙「路 B」可以从**盲扫**升级成**点名**

**实锤**：这台的开火链路**函数名 + 归属脚本全都拿到了**：

| 环节 | 函数 | 归属脚本 |
|---|---|---|
| **开火闸门** | `CanShoot` / `CanShootNow` | `CommonShootableComponent` |
| 发起开火 | `FireAction` | `ClientWeapon` / `ClientComponent` |
| 本地表现 | `EmitFire` / `ClearFire` | `ShootableComponent` / `FireComponent` |
| 上报 | `BroadcastShooted` | `CommonShootableComponent` |
| 瞄准 | `Aim` / `ClearLocalAim` | `ClientAimableComponent` / `CommonAimableComponent` |
| **射线** | `AsyncRaycast`（6 函数） | — |
| **弹药** | `AmmoModelComponent`（11 函数） | — |
| **后坐力** | `AimAdjuster`（7 函数） | — |
| 近战 | `CanWeaponMelee`、`AbortAllSkills` | `ClientWeapon` / `CommonSkill` |

⇒ 现在路 B 只按 `raycast` / `cast` / `cansee` 找 —— `AsyncRaycast` 能中，
但 **`EmitFire` / `FireAction` / `AimAdjuster` / `AmmoModelComponent` 这些不含关键词的全漏**。
应该把这批名字做成**优先候选表**。

### ④ B 层「按归属脚本分组」只显示前 25 个（**字母序**）→ 关键模块看不到

**实锤**：分组列表在 `AsyncRaycast`、`AnimationHolder` 之后就被截断，
而 `FireComponent` / `ClientWeapon` / `ShootableComponent` / `AmmoModelComponent`
**全都没显示**（字母序排在 `Animate` 之后）—— 要翻到 374 条命中清单里才能看到。

**修法**：分组显示**按"与功能相关的优先度"排**（武器 / 战斗 / 网络 / 交互 / 反作弊优先），
而不是纯字母序前 25。

### ⑤ 「无 `getconnections`」时 J 层的"谁在收"整列失效

**实锤**：本机执行器**没有 `getconnections`** ⇒ J 层每条通道的「收向监听」都是
`(无 getconnections)`（扫描已如实标注 ✅，没有假装）。这本身没 bug，但用户会以为"没人监听"。

**修法（低成本）**：在这种执行器上，把那一列合并成**一行说明**（"本机没有 getconnections ——
整列看不到，换带此 API 的执行器才能查"），而不是每条都打一遍。

### ⑥ `SCAN_EMERGENCY` 余量只剩 21%

**实锤**：629242 / 800000。再大一两档的地图就会撞上限。
**建议**：保持现有"**已达应急上限(数据可能不全)**"的醒目提示（9.9.10 已加），
并在报告顶部把 **实例总数 / 上限 / 占比** 一并打出来。
