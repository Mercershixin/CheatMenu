# 全功能「绕过覆盖」审计 · 初始 vs 最新对比 · 能否绕过（2026-09-23）

> 触发：用户要求「继续看老外的方法、学更多思路、**全部功能都加上**；我要知道**全部功能都有没有成功**；
> 一开始的和现在最新的**功能区别对比**；**能不能成功绕过**」。
> 本文件是**审计报告**，不是新功能提案。配套发版 **11.2.0**（隐身扩层 + 补一处隐身盲区）。

## 一、先说结论（四句话）

1. **能绕过的**：一切「在客户端可观测」的检测面 —— `debug.info` 找非 C 闭包、`getrenv()` 取副本、
   按栈层 `getfenv`、问线程身份、取 `debug.traceback`、按名找函数、`Clone`/`GetDescendants` 抓 GUI。
   本轮已把这些**全部盖上**（隐身 3 层 → **5 层**）。
2. **绕不过的（诚实边界，别抱幻想）**：**服务端判定**（伤害/血量/位置/踢出/封禁）、
   **逐帧遍历 GUI / 全图实例扫描**、**函数身份比对**（`getfunctionhash`/`compareinstances` 这类，除非对方用 `debug.info`）。
3. **最大破绽不在"有没有隐身"，而在 `Ray` 模块用了 `hookmetamethod(game,"__namecall")`**
   —— 全项目唯一的总入口 hook。**这既是可检测指纹、也是掉帧源**，而且**本仓自己在 v6.9.10 就因为同样原因把它从 `Prot` 删过一次**。
4. **"全部功能都加上"已完成**：7 个 hook 点全部登记 + 全部进卸载清单 + 全部纳入隐身收割；本轮**补上了一处真实盲区**（防回退未收割）。

## 三、⛔ 最大破绽：`Ray` 的 `hookmetamethod(game,"__namecall")`

- 位置：`Ray.Install()`（源码 ≈L14400）—— 这是**全项目唯一**的总入口 hook。
- 它做了什么：拦下**所有实例方法调用**，只对 `self==Workspace` 的 Raycast/FindPartOnRay 做改写。
- 已做的减害：`checkcaller()` 早退 + `self~=WS` 早退 + 精确字符串比较（v6.9.10）。
- **仍然存在的问题**：
  1. 它是"所有 `obj:Method()` 的必经之路" ⇒ **调用频率极高**，且是一眼可辨的 hook 指纹；
  2. **本仓自己在 v6.9.10 因为"极度掉帧 + 游戏交互异常"把同样的 `__namecall` 从 `Prot` 删掉过**（见源码
     `Prot.InstallHideGui` 上方注释）—— 同一个坑，`Ray` 还留着；
  3. 项目铁律写的是「`hookmetamethod(game,"__namecall")` 做**关键词搜索**＝绝对不行」；`Ray` 是**窄用**（只认 Workspace 的 3 个方法），
     属于**灰区**，不是纯粹违规，但**风险等级最高**。
- **可选处置（需你点头，我不擅自改）**：
  - **A（推荐·零风险）**：保留现状，仅在「防护」页加一句诚实提示 + 本文件留档；
  - **B（中等）**：把 `Ray` 改为**只走函数层 hook**（`Ray.HookFns` 已有），关掉 `__namecall` 层 ——
    代价：老式 `FindPartOnRayWithIgnoreList` 之外、走 Workspace 方法表的射线可能漏掉一部分；
  - **C（激进）**：完全删除 `__namecall` 层，静默瞄准只保留函数层 —— 兼容性下降最多。

| 统计 hook 数量 / 看 `__namecall` 是否被换 | ❌ | — | **Ray 的总入口 hook 藏不住** |

> **唯一"本该做得更好却没做"的是 `Ray` 的 `__namecall`** —— 见 §三，等你选 A/B/C。

## 八、点名核对：上帝 / 回血 / 加速 / 飞行 / 传送（2026-09-23 追问）

| 功能 | 实现方式 | 有没有 hook | 绕过措施 | 能不能绕 |
|---|---|:-:|---|---|
| **上帝 `GodMode`** | `SetStateEnabled(Dead/FallingDown/Ragdoll,false)` + `HealthChanged → Health=MaxHealth` + `CharacterAdded` 重绑 | **无** | 无 hook 指纹（本就不需要隐身） | ✅ 客户端不被打死/不倒下；❌ **服务端判死仍死**（伤害由服务端算，已取证） |
| **回血** | 就是上面那条 `HealthChanged` 回调（=上帝模式的一部分）+ Dead Rails 的「💚 立即回满血」按钮 | **无** | 同上 | ✅ 血条能顶回去；❌ 服务端判死时顶不住（DR 已取证） |
| **加速 `Speed`** | 改速度（`guardSpeed` 直通） | 无（但**会引发 `AntiRevert`**） | ✅ **`AntiRevert` 位置上报限速**（已纳入隐身收割） | ✅ 客户端跑得快；⚠ 服务端位置校验靠 `AntiRevert` 糊 |
| **飞行 `Fly`** | `BodyVelocity` / CFrame 循环 | 无（同上引发 `AntiRevert`） | ✅ `AntiRevert`（已纳入隐身） | ✅ 同上 |
| **传送 `TPEnabled`** | `root.CFrame=` **或** `tpStepChain` 分步传送（默认单步 ≤300 格）**或** `Humanoid:MoveTo` | **无** | ✅ **分步传送本身就是反瞬移**（把一次大跳拆成 N 小步） | ✅ 近/中距可；⚠ **远端可能被服务端拉回**；★ **故意不挂 `AntiRevert`** —— 挂了单步就被限速，等于传不过去 |

### 结论
- **这五个功能全都不 hook 任何游戏函数** ⇒ 它们**不需要隐身**；隐身 5 层只服务于 §二-A 那 7 个 hook 点。
- 它们真正的"绕过"是另一条线：**位置上报限速 `AntiRevert`（飞/加）+ 分步传送（TP）**。
  ★ 本轮已把 `AntiRevert` 补进隐身收割（§四），所以**飞/加的绕过分母也变干净了**。
- **绕不过的仍是服务端**：上帝/回血的"真无敌"做不到；TP 远端可能被拉回。
- ⚠ `AntiRevert` **只**在飞行/加速开着时挂（`SYS.SyncAntiRevert` 的条件就是 `Fly or Speed`）—— 这是**故意的**，不是漏。

## 九、破绽修复（11.2.1）

- 🧷 `Ray` 的「路 A」(`hookmetamethod(game,"__namecall")`) **改为默认不装** ⇒ **破绽已修**。
  默认只走「路 B」函数层（单点 `hookfunction`，合规）。
- 新增开关 `Prot_RayNamecall`（防护页 · 默认**关** · ⛔不推荐/有风险）：只在个别游戏射线不走可命名函数时才开。
- 「路 B」补齐 `CB_BlockRay`（阻挡射线）—— 原来只有路 A 支持它，路 A 关了就漏。
- **结果：全项目已无任何「默认启用」的 `__namecall`/`__index` 总入口 hook。**
