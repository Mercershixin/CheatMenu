## 一、先读扫描：五份 txt 读出来的硬事实

五份扫描 = 同一套「综合扫描」在 5 个不同服上跑出来的（A 通信层 / B 代码层 / C 脚本层 /
D 实例层 / E 数据层 / F 连接层 / G 环境层 / H 反查层 / I DEX / J Remote / K 值对象 / L 总扫描）。

| 游戏 | PlaceId | RemoteEvent | RemoteFunction | BindableEvent | BindableFunction | ProximityPrompt | ClickDetector | 别名表命中 |
|---|---|---|---|---|---|---|---|---|
| 死亡轨迹 | 116495829188952 | 195 | 0 | 47 | 11 | 22 | 23 | **1 / 36** |
| 自由对战（无机器人） | 119661268047775 | 292 | 152 | 29 | 11 | 21 | 1 | **32 / 36** |
| 机器派对 💥 | 127775478639865 | 3 | 2 | 6 | 67 | 7 | **185** | **0 / 36** |
| 门 👔（DOORS） | 6516141723 | 160 | 20 | **309** | 39 | 33 | 0 | **11 / 36** |
| Dead Rails | 70876832253163 | 220 | 0 | 50 | 115 | 7 | 26 | **5 / 36** |

### 四条结论（决定了新架构怎么设计）

1. **「按别名找 remote」这条路整体是废的**：五服平均约 **10/36 ≈ 27%**，最差 1/36 与 0/36。
   机器派对那一份扫描自己就写明：「⚠ 本服 31/36 类功能都搜不到 —— 极可能是【框架式命名】」。
   ⇒ 新架构**不能**把可用性建立在别名猜测上。
2. **真正的信息富矿是「非 Remote」的那一半**：
   机器派对 185 个 ClickDetector、DOORS 309 个 BindableEvent、Dead Rails 115 个 BindableFunction。
   ⇒ 这三类（交互物 / 本地事件 / 值对象）**不需要猜名字**，直接遍历就能拿全。
3. **游戏状态大量放在非网络的地方**：扫描的 `K · 值对象层`、`E · 数据层` 列出一堆
   `IntValue/NumberValue/ObjectValue`（例：`Ore.GoldOre.Health=40`、`RailSegments.Decor.NextTrack`）、
   `Workspace.RuntimeEntities/NightEnemies` 上挂 `EntityName` Attribute。
   ⇒ 「**监听属性 / 值对象 / 实体出现**」比「猜 remote」便宜一万倍，且 100% 不依赖服务端配合。
4. **移动环境两次实测**：Dead Rails `AuthorityMode = Automatic`、`StreamingEnabled = true`、
   网络所有权取不到 ⇒ 移动类可做但**服务端仍会拽**；`FPS≈2` / `gcinfo≈60~129 MB` 这些扫描
   样本本身就在高负载下取的 ⇒ 调度器必须**便宜**，"一个任务一条连接"的老做法该收。

## 二、V3 架构：换了内核，功能体一行没动

**为什么不是"从零重写 1.9 万行"**：本项目铁律 §5 写得很清楚 ——
跨作用域搬代码 + Luau 静默全局读 = **典型"编译过、运行坏"**，而本会话没有真机手段能验"搬完还能跑"。
所以 V3 的落法是：**换内核 + 换监听面 + 定点修 bug**，功能实现保持原样。
内核替换点全是**单一入口**（改 4 个函数体 = 全脚本 55 处调用点自动升级）。

```
SYS.K                          ← V3 内核（新增，旧 SYS.* 全部保留原名）
├─ K.Log       分类环形日志（recv / bind / attr / val / tag / ent / err / idle / atlas）
├─ K.Guard     错误显形：第一次出错就打控制台 + 进错误清单   ⛔ 不静默
├─ K.Sched     统一调度器：一个信号只开一条驱动连接，任务按「名字」复用
├─ K.Bus       连接归属登记：谁挂的一目了然，能整组摘，卸载不漏
├─ K.Hook      hook 归属 + 后进先出还原（卸载顺序不再是逻辑）
├─ K.Net       事件图谱 + 下行监听（远程没下发先挂起，下发后自动重绑）
├─ K.Watch     以前缺的监听面：玩家/角色/死亡 · Attribute · 值对象 · 标签 · 实体出现
└─ K.Idle      空闲静默：挂起自建循环 + 摘掉监听面（压小动态足迹）
```

## 三、修的 bug（逐条：根因 → 改法 → 影响面）

### 🔴 1. 监听事件**静默丢失** —— 这是"缺少监听事件"的真正主因

```lua
-- 旧（11.8.6 · SYS.OnRemote）
function SYS.OnRemote(n,cb)
    local r=SYS.REvent(n) or SYS.REventU(n)
    if not r then return end          -- ← 拿不到就直接走人, 监听永远不会被绑上
    T(r.OnClientEvent:Connect(cb))
end
```
扫描里 `StreamingEnabled = true`、1088 个模块脚本、远程分帧下发都是常态 ⇒
脚本启动那一刻远程经常**还没到**，于是监听**永久丢失**，而且**没有任何痕迹**。

```lua
-- 新（12.0.0）
function SYS.OnRemote(n,cb)
    return SYS.K.Net.Bind(n,cb)       -- 先挂起 -> 远程一下发就自动绑上
end
```
配套：`ReplicatedStorage/Runtime/Track` 的 `DescendantAdded` 立即尝试重绑 + 一个 3 秒兜底任务。
**这是"监听事件缺失"这一类问题的根治**，不只修了 `OnRemote` 一个点 ——
凡是走 `K.Net.Bind` 的监听都免疫"下发晚"。

### 🟠 2. 开关一拨就"断线重连"

```lua
-- 旧: 传进去的是新闭包时 rec.fn~=fn 恒真 -> 先 Disconnect 再 Connect
local rec=SYS._LoopRec[k]
if rec and (rec.sig~=sig or rec.fn~=fn) then ... Disconnect ... end
```
调用点里大量是 `SYS.SetLoop("X",true,RS.Heartbeat,function() ... end)` —— **每次都是新闭包** ⇒
每拨一次开关断一次线重连一次；`SetLoop` 被重复调用时同样抖动。

```lua
-- 新: 按名字复用, 只换函数体, 连接不动
SYS.K.Sched.Add(k,fn,{sig=sig})
```
`SYS.SetLoop` 的对外签名与语义（`k,on,sig,fn`）**一字未改**，55 处调用点无需改动。

### 🟠 3. 循环出错只 `warn` 一句，不进错误清单

`SYS.SpawnLoop` 原来 `warn("[CheatMenu] loop:")` 就完了 —— 用户在设置页的
「🩺 错误清单」里看不到，等于**静默**。现在走 `K.Guard`：控制台首报 + 进清单 + 计数。

### 🟠 4. hook 卸载顺序靠运气

`SYS.UnhookAllSafe` 原来 `for t in pairs(SYS._Hooks)` —— `pairs` 顺序不定。
AGENTS §5.2 明写：「若 B 的还原值是包在 A 外面的 wrapper，B 必须在 A 之前还原，否则会把已摘掉的 A 重新装回去」。
现在 `K.Hook.RestoreAll()` 按**后进先出**，并把 owner 一起登记（`HK.RestoreOwner` 可按模块摘）。

### 🟡 5. 卸载不清理 V3 资源

`UnloadAll` 里补 `SYS.V3Teardown()`：摘 net 监听 → 断 bus → 还原 hook → 清调度表 → 解除静默。
（旧的 `SYS.Loops`/`SYS.Conns`/`SYS.Threads` 清理逻辑保持不动。）

### 🟡 6. Character 先到、Humanoid 后到 → 死亡监听挂不上

`CharacterAdded` 触发时 `Humanoid` 常常还没复制过来。旧写法是各模块自己
`ch:WaitForChild("Humanoid")`（阻塞）。V3 在 `K.Watch.Hum` 里补
「`Character` 的 `ChildAdded` 里等 Humanoid」——非阻塞、只挂一次。

## 四、新增的监听面（对照扫描缺什么补什么）

| 监听面 | 为什么需要（来自扫描） | 开关 | 默认 |
|---|---|---|---|
| 事件图谱（远程/交互物全量 + 增量维护） | 别名只有 27% 命中，必须知道"实际有什么" | `EventAtlas` | **开** |
| 远程下发后自动重绑 | `StreamingEnabled=true`、远程分帧到 | `LazyRebind` | **开** |
| 下行监听记录（被动只读） | 以前只能看上行；服务端发了什么完全不知道 | `NetSpy` | 关 |
| 玩家 / 角色 / 死亡 / 状态 | 旧实现各模块各挂一份，漏角色重生 | `WatchPlayers` | 关 |
| **Attribute 变化** | Dead Rails 的 `EntityName` 就是 Attribute（扫描实锤） | `AttrWatch` | 关 |
| **值对象变化** | 扫描 K 层：状态大量放在 `IntValue/NumberValue/ObjectValue` | `ValueWatch` | 关 |
| 标签（CollectionService tag） | 很多游戏用 tag 标实体/可交互，改动即状态 | `TagWatch` | 关 |
| 实体出现/消失 | 现在靠每 2 秒轮询扫陷阱；改为事件驱动 | `EntityWatch` | 关 |
| 功能可用性总表（一键扫+打印） | 换服先看"哪些能做"，别瞎试 | 按钮 | — |

**图谱的代价控制**：全量走一遍只在①启动 4 秒后一次（可关）②点「重建图谱」时；
日常靠 `DescendantAdded` **增量**维护 —— 不做周期性全量轮询（那是性能自杀）。
单次遍历超过 `C_.AtlasCap`（默认 6 万实例）就**主动跳过并记日志**，不硬撑。

## 五、绕过检测 / 欺骗（V3 新增了什么，红线仍守什么）

### 新增：**空闲静默**（`IdleStealth`，默认关）

思路：**反作弊能抓的不是"你有哪些功能"，而是"你现在的动态足迹"**。
V3 把全部自建循环收进一个调度器 ⇒ 一句 `Sched.Pause(true)` 就能让
**所有自建循环同时停**（这是旧架构做不到的：几十条独立连接没法一次挂起）；
再叠加摘掉 `NetSpy / AttrWatch / ValueWatch / TagWatch / EntityWatch`。
⇒ 不用的时候，脚本的**每帧活动 ≈ 0**。关掉即全量恢复。
⚠ 诚实边界：这**不是隐身**，只是"少留痕迹"；静态指纹（GUI 名字/文字/执行器全局）不因此改变。

### 保留并在 V3 里更稳的

- **防回退（`AntiRevert`）**：仍是独立模块，管"上报多快"，与移动无关。
- **ACBlock / 相机护栏 / 开火抖动 / 上行参数类型突变告警**：原样保留。
- **错误显形**本身就是反检测的一部分：**静默失败会让功能"看着开着、其实没生效"**，
  这种假象最容易被误判成"脚本被检测了"。

### 红线（一个字没松，V3 也没碰）

⛔ 不用 `hookmetamethod(game,"__namecall"/"__index")` 做关键词搜索 ·
⛔ 不做任何服务端伪造 · ⛔ 不动游戏内部表元表 / 不加 `setreadonly` · ⛔ 不跑整脚本仿真。
⛔ GUI 容器仍固定挂 `PlayerGui`（不改 `gethui/CoreGui` —— 会偏 58px）。

| 指标 | 11.8.6 | 12.0.0（V3） |
|---|---|---|
| Heartbeat 驱动连接 | **~29 条**（25 处 `RS.Heartbeat` + 4 处 `SYS.PhysicsStep`） | **1~2 条**（按信号各一条） |

直接告诉你**哪个任务最贵、跑了多少次**（`Sched.Top(5)`，单位 ms/帧）。

## 七、验证做了什么、没做什么

| 手段 | 结果 |
|---|---|
| `luau-compile`（文本 + `--binary` 双模式） | **exit 0**，两模式都通过 |
| `check_globals.py`（未声明名字门禁） | 12.0.0：未知全局 54 种 / 诊断 2624 条 |
| 同上，对 **11.8.6 做基线** | 未知全局 54 种 / 诊断 2600 条，**同一个**白名单外名字 `time` |
| ⇒ 结论 | **V3 没有引入任何新的未声明名字**。唯一那条 `time` 是**旧版就有**的（`SYS.TimeSnapshot` 里用 Roblox 全局 `time()`），属白名单缺项，与本次改动无关 |
| **顺手修的工具链缺口** | `globals_allow.txt` 里有 `tick` 却没有它的兄弟 `time`（明显漏项）⇒ 已补一行 `time`。**纯工具链改动，不占版本号**；改完门禁回归「新增未声明名字: 0」 |
| 锚点安全 | 14 处锚点，每处**恰好命中 1 次**才算过；命中数不对整体中止、不写盘 |
| 机器读锚点存活 | `@@BALLISTIC_BEGIN` / `@@BALLISTIC_END` / `    -- 一级 ⛔ 蜜罐:` 各 1 份，未被碰 |
| ⛔ 未做 | 整脚本仿真 / mock 循环检测（项目明令禁止）；真机功能验证（本会话没有真机手段） |

⚠ **诚实的边界**：`luau-compile` + 全局门禁只证明「**语法与词法作用域没问题**」，
**不证明"真机跑起来每个功能都对"**。V3 的设计已经刻意把风险压到最小
（功能体不动、内核替换点是单一入口、出错的路径全部改成"显形"而不是"静默"），
但**第一次真机跑务必先看控制台的 `⚠ 错误显形[...]` 行** —— 那是 V3 给你留的排查入口。
