## 二、"高亮不彻底"的三个机制（已逐条处理）

### ① 深度预算太小 → 深层交互件被截断 ✅ 已修

`deepHasI`（判断"模型里有没有交互件"的下钻器）原来 **深度上限 8 / 节点预算 4000**。
DOORS 那种 `Model → DrawerContainer → Knob → ActivateEventPrompt` 的结构，
Node 一多就**在够到提示之前把预算烧完** ⇒ 看起来"这个抽屉就是没亮"。

**改**：深度 **8 → 11**、节点预算 **4000 → 9000**。外层本来就有 120ms 时间预算兜底
（到点用已有结果收尾，不会卡帧）。

### ② 一个模型只亮 12 个子件 → 大半被截掉 ✅ 已修

`if _n>12 then break end`。实测机器派对一个"限时掉落商店"人偶身上挂了 **20+ 个 ClickDetector**，
12 个上限直接把大半截掉。

**改**：**12 → 40**。

### ③ 游戏主动把可交互物藏起来 → 引擎层面画不出来 ⚠ 只能如实报告

`HidePickup` / `HidePrompts` / `HideMonster` 这三条 remote 说明游戏会把东西**藏起来**
（典型做法：设 Parent=nil）。而：

- `SYS.Index()` = `WS:GetDescendants()` ⇒ **只看得到有父级的实例**，藏起来的扫不到；
- 更关键：**即使扫到了也画不出来** —— `Highlight.Adornee` 必须是一个**在 DataModel 里**的
  BasePart/Model，父级为空的实例**没有 3D 存在**。

⇒ 这**不是判据漏了**，是引擎限制。所以本轮的做法是：
新增 **「🩺 高亮彻底性自检」** 按钮，把「被藏起来的实例有几件」**如实报出来**，
并明确写清"不是判据漏了，是画不了"。**不假装能亮。**

## 三、新增：🩺 高亮彻底性自检（物件透视下方）

点一下会在控制台打出：

```
[CheatMenu] ===== 物件透视 · 彻底性自检 =====
· 本轮 Workspace 实例: N 个 (透视只看得到有父级的实例)
· 本轮真正挂上高亮的载体: M 个 (池里 K)
· 游戏【藏起来】的实例: X 个(父级为空) —— 其中可交互/部件类 Y 个
  ⇒ 这些【引擎层面画不出来】…不是判据漏了, 是画不了。
怎么读:
  · 载体数 0 而实例数很大 -> 判据/预算出了问题, 把这张图的名字发我
  · 载体数正常但你还是没看到某类物件 -> 把那个物件的完整路径发我, 我按路径加判据
```

**这就是"彻底"的正确做法**：不是无限放宽预算（那会掉帧），而是**让你一眼看出到底是哪一类没亮**。
