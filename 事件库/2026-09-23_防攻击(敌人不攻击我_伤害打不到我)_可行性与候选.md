## 〇 · 一句话结论

**「伤害打不到我」在"服务端算伤害"的游戏里 = ⛔ 做不到**（和「真无敌」是同一个天花板，见 §一 判据）。
**能做的**是三件别的事：**① 打得到但立刻恢复**（已有：锁血+补血）· **② 提前看见 + 躲开**（已有：敌我判定补强）· **③ 还留着一个没验证的口子**——**客户端命中登记**（§三 Q1/Q2/Q5，**必须先只读探针**）。

★ 公开项目（GitHub + 聚合站）里**没有任何一家给出可信的 Dead Rails 真免伤** —— 它们自己的功能表就写着 **`God Mode (Limited Versions)`**。

## 一 · 判据：不问"游戏怎么吹"，只问三件事

判断"防攻击"能不能做，只看这三点（**三点全占 = 做不到**）：

1. **伤害是谁算的？** —— 有没有「我出事了」的**客户端上行通道**。
2. **客户端有没有"血量面"？** —— Value 对象 / Attribute / 可写 `Humanoid`。
3. **有没有服务端权威痕迹？** —— `Replica` / `jecs`(ECS) / `validate*` / `*Telemetry` / 服务端 Attribute。

### 跨游戏矩阵（★ 这是本文最有价值的一张表）

| 游戏 | 伤害谁算 | 客户端有血量面吗 | 客户端能上报命中吗 | ⇒「伤害打不到我」 |
|---|---|---|---|---|
| **Dead Rails** | **服务端**（`Replica` + `jecs` + `validateLivingCharacter` + `DeathFlowTelemetry` + 服务端 Attribute `HasDied`） | ❌ 玩家 23 个 Attribute 里**没有 Health**；全图 `Health` **只有 `Ore.*`** | ❌ 220 个 remote 里跟血量相关的只有 `bandage.Use` / `snake_oil.Use` / `RevivePlayer`（**全是"用药"**） | **⛔** |
| **FFA 对战服** | 服务端（`EntityService.TouchDamage` / `BeDamagedUnreliable` = 服务端结算） | 部分（玩家 37~42 个 Attribute，含 `BeDamage` 时间戳） | ⚠ **有**：`CombatService.ActionEvent` / `UnreliableActionEvent` = **客户端上报动作** | ⚠ 理论可发假命中，**但参数不明 + 服务端可能校验 + 会被记 ⇒ 未真机验证前不动** |
| **MM2 类** | 服务端（Madwork） | ❌（连换弹都无 remote） | 未见 | **⛔**（只能读 `DamageDenyInform` = "伤害被拒"提示） |
| **机器派对** | 小游戏内自成一套 | — | `AutoHitScan` / `AutoHitTick` / `SetNoDeath` 是**小游戏自己的函数名** | ⚠ 只在小游戏里可能，需单独取证 |
| **DOORS** | 服务端（怪物伤害是脚本判定） | ❌ | 未见 | **⛔**（现有 `TrapImmune` 只管陷阱/环境伤害，不是"生物打不到我"） |

### Dead Rails 单独详证（本机实证，不是猜的）

- 玩家角色 Model 的 23 个 Attribute：`ArrowAmmo` / `CurrentStamina` / `InCombat` / `isSprinting` / `BloodColor`… —— **没有 Health**。
- 全扫描 `grep Health`：**只命中 `Workspace.Ore.{CoalOre,GoldOre,SilverOre}.Health`（IntValue=40）** ——
  **玩家与敌人都不存在客户端可见的血量对象**。⇒ 血量活在 **`jecs`(ECS) 组件**里、由服务端算，
  `Replica` 只把"渲染需要的那点状态"复制过来。
- 敌人伤害值（**只读可显示**，这是能做的）：
  | 敌 | 字段 | 值 |
  |---|---|---|
  | `Workspace.NightEnemies.Model_Vampire` | `Configuration.Damage` | **15** |
  | `Workspace.Sterling.Enemies.Model_Werewolf` | `Configuration.Damage` | **35** |
  | `Workspace.RuntimeEntities.Model_RifleSoldier.Bolt Action Rifle` | `WeaponConfiguration.BulletDamage` | **70** |
  | `Workspace.ObjectModels.maxim_gun` | `Configuration.BaseDamage` / `WeaponConfiguration.BulletDamage` | **75** / 15 |
- `RemoteEvent.Hurt`（`ReplicatedStorage.Shared.Universe.Network.RemoteEvent.Hurt`）**存在**，
  但**方向未定** —— 本机没有 `getconnections`，扫描如实标 `收向监听: —`。
  ⇒ 大概率是**服务端→客户端**的受伤通知（和 `Hitmarker` 一起），**只能拿来"感知受伤"，改变不了结算**。
- 客户端侧确实有一整套战斗模块（`ClientHitRegistration` / `HitRegistration` / `ClientMeleeHandler` /
  `MeleeUtil` / `pickMeleeTarget` / `replicatedProjectileClientHandlers` / `clientTurretSystem` / `PhysicsIncidentClient`），
  但**它们服务的是"玩家打敌人"**；敌人是服务端实体（`RuntimeEntities` / `NightEnemies`），攻击由服务端结算。

### 2.2 它们**实际**提供的能力（★★ 这一节比"谁有 God Mode"有用得多）

| 公开脚本的能力 | 真实含义 | 我们对应 / 可否做 |
|---|---|---|
| **ESP 僵尸 / 夜敌 / 野怪** | 提前看到 → 躲开 | ✅ **已做**（B5 敌我判定补强） |
| **Enemy Health Display** | 显示敌人血量 —— 前提是**服务端有可见面** | ⚠ Dead Rails **没有可见血量面** ⇒ 这个功能**在这游戏做不了** |
| **Hitbox Extender**（Hitbox Zombies / Night） | 把**敌人**的 hitbox 撑大，让你**更容易打中他** —— **是进攻，不是防御** | 属"我们打得更准"，**不在本主题** |
| **Aimbot Night Enemies** | 同上 | 同上 |
| **Auto Use Bandage** | 自动吃绷带 —— 那是**服务端认的真回血**（走 `bandage.Use`） | ⚠ 是"自动用道具"，**不是免伤**；可做，但属另一条 |
| **Auto Avoid Hazards** | 自动躲环境伤害 | ✅ 思路可借（预警 + 自动移动），是"躲"不是"免" |
| **NPC lock / Freecam** | 锁定/观察目标 | 不在本主题 |
| **`God Mode (Limited Versions)`** | ★★ 聚合页原文：*"God Mode (Limited Versions): Never die and **endure** enemy attacks"* | **它们自己标了 Limited；"扛住" ≠ "免疫"** ⇒ 与我们结论一致 |

### 2.3 主流技术手法只有两类 —— 而**第二类本项目明令禁止**

1. **写回 `Humanoid.Health`**（`Heartbeat` 循环 / `HealthChanged` / `GetPropertyChangedSignal("Health")`）
   —— **= 我们已经做的 `SYS.DRHp` 锁血+补血**。
   在服务端权威游戏里会被复制包压回 ⇒ 只能"血条满，服务端判死仍死"。
2. **`hookmetamethod(game, "__namecall" / "__index")` 拦 `Humanoid:TakeDamage`** ——
   ⛔⛔ **本项目铁律明令禁止**（挂总入口 = "开过检测极度卡顿掉帧"的病根，且它本身就是最明显的检测指纹）。
   ⇒ **就算它在某个游戏真有效，我们也不走这条路。** 要拦只能"单点 `hookfunction` 一个具名函数"，绝不是总入口。

> ★ 顺带一条正面发现：`MicroHub` 专门带了个 `fastWordSearch.lua`（Trie 关键词搜索 DataModel）
> ⇒ 说明**公开 hub 也是按名字关键词找东西**，和我们 B5「敌我判定补强」是同一个思路 —— 我们没走偏。

## 三 · 候选清单（**只报，等你挑编号**）

> 与 2026-09-22 那两份候选清单同格式：**编号 · 功能 · 依据 · 动作 · 风险**。

### 🟢 现在就能做（纯客户端 / 只读，零风险）

| 编号 | 功能 | 依据 | 动作 | 风险 |
|---|---|---|---|---|
| **P1** | **受伤感知 HUD**：屏幕红闪 + "刚刚被打" + 3 秒内受击次数 | `RemoteEvent.Hurt`（★ 方向需真机确认）+ 客户端可读 `Humanoid.Health` | 只监听 | 低 |
| **P2** | **敌人伤害值只读显示**：在敌人 ESP 标签旁标「打你 15 / 35 / 70」 | §一 实测的 4 个 `Configuration.Damage` / `BulletDamage` | 纯读 | 无 |
| **P3** | **近身预警**：敌对生物进入 N 格 → 边框闪 + 文字/音提示 | `Workspace.RuntimeEntities` / `NightEnemies`（已有敌对判定 `drHostile`） | 纯读 + 距离计算 | 无 |
| **P4** | **受击即补**：收到 `Hurt` 立刻 `Refill`，而不是等 `HealthChanged` 的下一帧 | `RemoteEvent.Hurt` + 现有 `SYS.DRHp.Refill` | 只监听 + 同帧写回 | 低（仍是本地） |

> ⚠ P1~P4 都是 **"看得见 / 躲得开 / 扛得住"**，**不是"打不到我"** —— 这就是本主题在服务端权威游戏里的天花板。
> ★ P1/P3 的思路**跨游戏通用**（FFA 有 `BeDamagedUnreliable` 可做命中确认，MM2 有 `DamageDenyInform` 可做"伤害被拒"提示）。

### 🟡 需要先做**只读探针**（不改行为）才敢下结论

| 编号 | 探针目标 | 想回答的问题 | 依据 |
|---|---|---|---|
| **Q1** | `ClientHitRegistration`(3) / `HitRegistration`(3) | **敌人→我**的命中，是不是**客户端**登记后上报？若是 ⇒ 才有"打不到我"的可能 | 客户端脚本清单 |
| **Q2** | `replicatedProjectileClientHandlers`(19) 的 `raycastReplicatedProjectile` / `clientProjectileInit` / `bulletImpact` | 复制子弹的**命中判定**跑在哪端？ | 战斗脚本全清单（⚠ 它旁边就是 `validateWeapon`，**校验绝不能碰**） |
| **Q3** | `RemoteEvent.Hurt` 的**方向**（下行 / 上行） | 是不是纯下行通知？ | 需真机 / 换带 `getconnections` 的执行器 |
| **Q4** | `SetNoDeath`（扫描 GC 命中，**归属脚本未知**） | 是游戏自己的函数还是第三方？挂哪端？ | `名字可疑的函数` 命中表 |
| **Q5** | `ClientMeleeHandler`(9) / `MeleeUtil`(7) / `pickMeleeTarget`(2) | 近战命中的**目标选择**是否在客户端？ | 同上 |

★ **探针规范**（沿用本项目既有做法）：**只把"调用次数 / 参数类型"打到 F9，`return orig(...)` 原样转发，绝不改行为**
（同 `DeadRails_AimProbe` 的写法）。
⚠ 且**只允许单点 `hookfunction`**；`__namecall` / `__index` 总入口一律不挂。
★ 探针必须挂进 `UnloadAll`（本项目硬规矩：任何 hook 都要能卸干净）。

### 🔴 明确不做（省你时间，别再问）

| 项 | 为什么 |
|---|---|
| 真·免伤 / 无敌 /「伤害打不到我」 | 服务端算伤害 + 客户端无血量面 + 无上行通道 ⇒ **三条占满**，⛔ |
| `hookmetamethod` 拦 `TakeDamage` | 本项目铁律禁止（总入口 hook） |
| 改敌人 `Configuration.Damage` / `BulletDamage` | 这些是**客户端只读副本**，改了服务端不认（服务端读自己的值） |
| 把敌人血量改 0「让它死在我这边」 | 敌人血量同样不在客户端（全图只有 `Ore.*` 有 `Health`），且实体由服务端 `jecs` 删 |
| 发假命中给服务端（FFA 那种 `ActionEvent`） | Dead Rails **没有**这条上行通道；别拿别的游戏的经验套 |

## 四 · 诚实边界（必须说清，别让你抱错期望）

- **"打不到我"= 做不到**；**"打不疼"**（本地补血）= 已有且**会回弹**；**"提前看见 + 躲开"**= 已做 / 可做。
- `RemoteEvent.Hurt` 的**方向没验**（本机无 `getconnections`）⇒ **P1 / P4 要真机确认一次**才好用。
- **Q1 / Q2 / Q5 是唯一还能翻盘的口子**：如果 Dead Rails 的命中判定真在客户端登记，才可能做出"打不到我"。
  **但必须先只读探针 + 真机验证；在那之前我不做任何承诺。**
- 公开项目**没有任何可读的 Dead Rails 真免伤实现**（全混淆，且自己标 `Limited`）——
  所以**不能拿它们当"别人能做到"的证据**。
- 本主题是**跨游戏**的：FFA 的 `EntityService.DamageShield` / `DamageImmunity` 是**权威只读**免伤状态
  （可以做"HUD 显示我现在有没有盾"），但 **≠ 能给自己加盾**。
