一、为什么需要：线性提前量补不了"子弹自己会掉"

现有「📐 预测瞄准」做的是线性提前量：

瞄准点 = 目标位置 + 目标速度 × 提前量秒数

它假设子弹是瞬发的（hitscan，一扣扳机即刻判定）。这个假设对枪械成立，但对 抛射物武器（弓 / 火箭筒 / 手雷 / 雪球 / 投掷物）不成立 —— 有两个线性提前量补不了的东西：

漏掉的因素后果
子弹要飞一段时间才到（不是瞬发）提前量按"目标移动"算，但飞行时间本身也在变
子弹在飞的过程中被重力往下拽瞄"目标 t 秒后的位置"打出去，子弹落点在其下方 → 远距离永远打低

二、算法：把三件事一起解，得到关于 t 的四次方程

求时间 t，使「从枪口以初速 s 打出、受重力 g 下坠的子弹」 正好在 t 秒后撞上「以 v 匀速移动的目标」。

约束是"发射速度向量的模 = 初速"，即 |u|² = s²，展开后：

l = -½g,  (h,j,k) = 目标相对位移,  (p,q,r) = 目标速度

(l²)t⁴ + (-2ql)t³ + (q² - 2jl - s² + p² + r²)t² + (2jq + 2hp + 2kr)t + (j² + h² + k²) = 0

用 Ferrari 降次闭式求根（bpQuartic → bpCubic → bpQuadric）， 取最小正根（最早的物理交点），再回代出正确的枪口朝向。 返回的点语义是 origin + u（u = 需要的发射速度向量）， 只能当 CFrame.lookAt 的目标点用 —— 方向对，它不是"目标的位置"。

三、形态：独立开关、默认关、老路径零改动

下坠加速度CB_ProjGrav = 196.2滑块 0~400；0 = 不补下坠（只补飞行时间）

为什么老行为一定不变

  • 开关默认关 ⇒ 那段代码根本不执行。
  • 接入方式是在 leadPos() 里加一条分支，不是替换： 开关开 → 尝试解交点；解不出来（超射程 / 初速填错 / 目标在逃离）→ 静默退回原来的线性路径。
  • 与「📐 预测瞄准」是两条独立路径，谁开谁生效，不互相覆盖。
  • 返回值刻意与线性路径语义对齐（"相机该朝的方向上的一个点"）， 所以 aimTick / fireTick 里那 3 处 leadPos() 调用一行都没改 —— 风险面被压到最小。

四、相对上游的 4 处改动（其余逐行保真）

#改动原因
a剥掉"气球 / 跳跃玩家重力"的 Raycast 分支 那是某个具体游戏的反物理补偿（读 InflatedBalloons / IsOwlTarget 这类游戏私有 Attribute），通用菜单里没有对应物
b取最小正根（最早交点） 上游取"第一个正根"，而遍历顺序是三次求根顺序排的、不保证最小 → 会随机落到较晚的交点
c补一条 gravity<=0 的二次方程分支 上游那条路 c0 = l² = 0 要作除数 → 出 NaN
d补回 r=0 降次分支被漏掉的 y=0 根 上游只解了三次 y³+py+q=0，漏了 y·(y³+py+q) 里的 y=0

实现里的一个真坑（已处理）：bpCubic 必须把"没有的根"显式置 nil —— Lua 里 0 是真值。留着占位的 0，上层 if a then 就会把它当成 "这个根存在、值是 0"而多解一遍。上游用 {solveCubic(...)} 靠表构造的 nil 截断规避； 我们返回多值，就得自己清干净。
