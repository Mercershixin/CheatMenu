## 一、公开脚本有、我们没有（按价值排序）

对照来源：DOORS 专项脚本（haxhell / cheatheaven）、通用执行器指南（Delta/Infinite Yield/CMD-X），全部为 2025–2026 公开版本。

| # | 能力 | 公开脚本叫法 | 我们现状 | 可行性 |
|---|---|---|---|---|
| 1 | ★★ **怪靠近自动钻进藏身点** | Auto Hide | 只有 `AutoDodge`（自动躲**伤害机关**，且只在 MachineParty 用） | ✅ 能 —— 走**服务端通道**（DOORS 的 `HidePickup` / `GetOutOfHiding` 已在抓包里确认存在）。这是"真正不死"的唯一正路 |
| 2 | ★★ **表现层屏蔽** | Block Handlers | 无 | ✅ 能（纯客户端）：`Jumpscare` / `SpiderJumpscare` / `CamShake` / `Vignette` / `Ragdoll` / `Cutscene` 都是**服务端→客户端的通知**，hook 掉就不会播（服务端照样判你死，但体验上"不吓人、不卡"） |
| 3 | ★ **交互耗时归零 / 隔墙交互 / 加长交互距离** | Instant Interact / Interact Through Walls / Interaction Range | 无 | ✅ 能（改 `ProximityPrompt.HoldDuration` / `MaxActivationDistance`，本地生效；服务端一般只校验距离与权限） |
| 4 | ★ **自动解密码**（Library / Padlock） | Auto Padlock | 无 | ⚠ 半能：密码书 `LiveHintBook` / 提示纸 `LibraryHintPaper` 能读到文字 → 可以**自动读+显示**；**提交**仍要过服务端 |
| 5 | 全亮 | Fullbright | ✅ 有（光照档位 / 禁雾，6.10.4 补了入口） | 已完成 |
| 6 | 物品 / 门 / 衣柜 / 玩家 ESP | Target ESP | ✅ 有，而且更细（分类判据 + 祖先链 + 形状兜底） | 已完成 |
| 7 | 反 Rush / Seek 预警 | Anti Rush / Anti Seek | ⚠ 曾有「反陷阱预警」，用户要求删了 UI（6.9.33） | 可重做成"**敌对生物靠近预警**"（配合生物透视的红标） |

> **结论**：我们缺的不是 ESP（那块比公开脚本强），而是 **①自动藏身 ②表现层屏蔽 ③交互增强** 这三块"体感型"能力。

## 三、建议执行批次

### 批次 1 —— 直接解决"上帝模式还是被杀"的体感（最高价值）
1. **Block Handlers 表现层屏蔽**（纯客户端，安全）：
   开关一个，hook/屏蔽 `Jumpscare`、`SpiderJumpscare`、`CamShake(Relative)`、`Vignette`、`Ragdoll`、`FlashSpecify`、`Cutscene(Followup)` + `Humanoid:SetStateEnabled(Ragdoll/Physics,false)`。
2. **Auto Hide 自动藏身**（走服务端通道）：
   探到敌对生物进入 N 格 → 就近找藏身点（`Assets.Bed/Wardrobe/...` 带 `HidePrompt` 的部件）→ 触发 `ProximityPrompt`（等价于你按 E，服务端认可）。
   ⚠ 只对"有藏身点"的游戏有效（DOORS 就是）；没有藏身点的游戏退化成"反向走位"。

### 批次 2 —— 交互增强
3. **Instant Interact**：把所有 `ProximityPrompt.HoldDuration` 归零（本地视角即可见效果）。
4. **Interaction Range**：`ProximityPrompt.MaxActivationDistance` 拉大（滑块 10~200 格）。
5. **隔墙交互**：配合 `ClickDetector` 的 `MaxActivationDistance` 一起拉大。

### 批次 3 —— 清理与收口
6. 日志标志重置（问题 3）、小游戏并入物件透视（问题 4）、老配置键清理（问题 6）、挂机页标签归位（问题 7）。

## 四、不能做 / 不要做的（写清楚免得以后重复问）

## 五、公开资料的两条硬结论（值得记）

1. **所有公开脚本的 "God Mode" 都只是本地拦伤害** —— 它们自己的措辞就是 *"prevents **most** sources of damage and death"*。
   真正让它们"不死"的是 **Auto Hide（自动藏）+ Block Handlers（屏蔽表现）** 的组合，而不是什么服务端绕过。
2. **封号风险主要来自"行为"而不是"脚本本身"**：过时执行器 + 在热门服里飞天/瞬移/乱杀 → 被举报 → 人工复核。
   → 所以**视觉类（透视/光照/屏蔽表现）风险最低，自动打人/修改存档风险最高**。这条直接决定我们做功能的优先级。
