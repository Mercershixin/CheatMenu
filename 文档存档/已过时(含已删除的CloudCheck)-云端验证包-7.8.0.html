CheatMenu 云端验证包 · 7.8.0

2026-09-20 · 仓库 Mercershixin/CheatMenu @ main · 目标：把「③ 云端执行（OCALE）」这一环补齐

这份东西要解决什么

本项目只认三类验证：① 静态分析 ② 单元测试 ③ 云端执行（OCALE）。 ①②已在本机跑完并全绿。③必须在真实执行器 / 云端跑——7.8.0 新增的 SYS.CloudCheck() 就是为这一环做的：一次点击，产出一段固定格式的 [PASS]/[FAIL]/[WARN] 清单，你原样发回来我就能逐行比对。

第 1 步 · 云端执行器（跑加载期 + API 层）

1

粘贴加载器

在云端执行器里跑仓库根目录的 loader.lua（就是那 45 行），或者直接用这一行：

loadstring(game:HttpGet("https://raw.githubusercontent.com/Mercershixin/CheatMenu/main/CheatMenu.lua"))()

加载器内置 8 个下载源兜底（raw → jsDelivr → fastly → gcore → githack → gitmirror → ghproxy → ghfast）， 并带时间戳查询参数绕开 CDN 缓存。

2

先确认"跑的是哪一版"（两条指纹）

[CheatMenu] 下载完成 473126 字节 <- https://...
[CheatMenu] build 2026-09-20 ... sha xxxxxxxx bytes 473126
  • 下载完成 N 字节 = 加载器拿到的产物大小 → 7.8.0 应为 473126。
  • [CheatMenu] build ... sha ... bytes ... = 产物自带横幅（每次发版生成）→ 用它确认不是 CDN 旧缓存。

若字节数对不上，说明拿到的是缓存/旧版 —— 多跑几次加载器，或换一个下载源。

3

打开菜单 → 设置页 → 点「☁ 跑一次云端自检」

菜单默认热键 G（右 Shift 始终可用）。按钮在设置页最下方区块 「☁ 云端执行自检 (OCALE)」。旁边还有 「📋 复制上次自检报告」。

报告会同时进三处：控制台（F9） · cloudcheck.txt · 剪贴板。

4

把这两段发我

  1. 上面那两行指纹横幅（下载完成 … 与 build …）；
  2. 自检的整段输出，至少要有以 [RESULT] 开头的那一行。

判读规则：FAIL=0 即这一环通过；FAIL>0 按下面的签名表对号入座。

云端执行器拿不到什么（别在这条路上问这些）

它只跑 Lua 沙箱，没有 Roblox 渲染管线。所以：画面是否正常、ESP 有没有真的描边、 菜单在手机上是否点得到、帧率掉不掉、Highlight 有没有被引擎回收 —— 在这里全都看不到。 这些必须在第 2 步的「云真机」看。不要用云端执行器的结果去推断画面表现。

第 2 步 · 云真机（唯一能给 G9 出数字的地方）

为什么 G9 只能在这里测

Highlight 的配额与回收发生在 Roblox 客户端的渲染与实例管理层，不在 Lua 沙箱里。 云端执行器里 Instance.new("Highlight") 只是建了个对象、从不进渲染路径，数出来的数字是假象； 而且"人多"这个前提要求同一局里真有大量角色，云端执行器通常跑空场景 —— 更假。

1

场景要求

  • 云真机（Android + Roblox + 执行器），进人多的公共服，同屏 ≥10 个角色（越多越好）。
  • 脚本用 7.8.0；打开玩家透视（每目标一个 Highlight）+ 需要的话开全图高亮。
2

测什么（三条，逐条记）

  1. 数量对不对得上：开透视后，实际带 Highlight 的角色数 == 你看到描边的角色数？
  2. 有没有被回收
  3. 帧率拐点：从 1 人 → 10 人 → 20 人，帧率怎么掉。
3

计数与测帧率的控制台小抄

Highlight 是挂在角色身上的（h.Parent = 角色，不是固定容器），所以这样数：

local n,t=0,0
for _,pl in ipairs(game:GetService("Players"):GetPlayers()) do
    local c=pl.Character
    if c then
        t=t+1
        if c:FindFirstChildOfClass("Highlight") then n=n+1 end
    end
end
print(("Highlight=%d / 角色=%d"):format(n,t))

测 3 秒平均帧率：

local f=0
local c=game:GetService("RunService").RenderStepped:Connect(function() f=f+1 end)
task.wait(3) c:Disconnect()
print(("FPS=%.1f"):format(f/3))

建议在 1 人 / 10 人 / 20 人三个时刻各跑一次这两段，把数字发我 —— 这就是 G9 要的量化。

第 3 步 · 顺带说清：官方 Open Cloud 与这件事无关

Roblox 官方 Open Cloud（DataStore / 资产 / 发布）只能从服务器外部读写数据与发布资产， 没有任何注入第三方 Lua 脚本的入口。所以它验证不了脚本，跟本项目这三类验证是平行的两条线 —— 除非以后要做"配置云同步"，否则用不上。

这一版的边界（我这边如实说明）

  • 7.8.0 的改动只加了一次性探测 + 一个只读自检函数 + 设置页两个按钮，不碰任何热路径逻辑。
  • 「视线 4 参降级」最坏情况 = 回到 7.6.1 的 2 参行为，不会更差 —— 这是设计目标，不是妥协。
  • SYS.CloudCheck 是只读的：不改配置、不建实例、不动角色。
  • 仍然不做整脚本仿真 / 循环检测（按用户要求彻底禁用）。
