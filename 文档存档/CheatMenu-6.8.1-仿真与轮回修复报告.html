第 4 个 bug：词法作用域门禁（7/7）抓到的

白名单之外的新名字: checkcaller, getnamecallmethod, h, hookmetamethod, newcclosure, old

h / old 不是"没声明"，而是**在 local 声明之前就被闭包引用了**：

local h=hookmetamethod(game,"__namecall",newcclosure(function(...)
    return h(self,...)      -- ← 这里的 h 解析成【全局 h】(nil)！
end))
这是严重 bug：钩子一被游戏调用就 attempt to call a nil value (global 'h') —— 等于把游戏的 __namecall 直接打断。4 处（踢人拦截 / 传送拦截 / GUI 枚举隐藏 / 射线改写）全部改成先 local h / local old 再引用。 另外 4 个执行器全局（hookmetamethod 等）确属有意新增 → 进了白名单（54 → 58）。

三、为什么"完整仿真"一直跑不完 —— 查清了

发现证据 / 处理
仿真台 HttpGet 桩返回假数据 对任何未登记 URL 都返回字符串 "RESP" → 更新检查把它当成"远端版本号" → 判定有新版本 → 走热重载链 → 永久卡死。 实测改造前的 6.6.0 同样卡死 = 一直以来的缺陷 → 改为抛错（与真实执行器拉不到时一致）
工具链 O(n²) 文本处理 split_code_strings 的每字符循环里写 re.match(pat, src[i:]) —— 每次都对整串做一次全量拷贝。 源文件 562KB→684KB 后，diag_inject / check / build_dist / run_full / run_probe_v69 集体超时 → 13 处改成 re.compile(pat).match(src, i)（线性，语义相同）
效果：check.py 3 分钟 → 0.9 秒；build_dist 5.5 分钟 → 1.4 秒
8 个残留仿真进程抢 CPU 之前几次超时的仿真进程没退出，累计上亿毫秒用户态时间，把后续所有测试一起拖死 → 全部清理
仿真台断言过期 「9 个页面全部存在」→ 我们现在是 11 页 → 更新为「页面数量与 UI.Defs 一致(11 页)」

四、新武器：加载阶段「有界冒烟」（1.1 秒）

完整仿真在本机落在一个既有的死循环里跑不完，所以它长期不是一个有效门禁。
但它真正有价值的是加载阶段（桩环境 + 顶层执行 + CreateMenu + 页面/模块自检）—— 上面那个致命 bug 正是这儿抓到的。
于是把这一段截出来单独跑：
  • sim/smoke_load.lua = full_sim.lua 截到「交互: 点击所有按钮」之前 + 汇总
  • sim/run_smoke.py = run_full.py 换目标文件
  • 1.1 秒返回，结果确定（12 通过 / 0 失败 / 被吞错误 0 条）

已接进 verify_all.py 作为 3.5/7 硬门禁； 三个完整仿真步骤（4/7、5/7、6/7）降级为「信息项」 —— 跑不完不算交付失败，但一旦产出结果就严格判。
