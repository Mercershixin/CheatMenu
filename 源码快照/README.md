# 源码快照

这个目录放 **`CheatMenu-<版本>.lua` —— 带注释的完整源码**，每个发行版一份。

## 为什么有这个目录

仓库根目录的 `CheatMenu.lua` 是**发行产物**（去注释、去缩进、minify 过）。它能跑，但**读不了** ——
没有注释、没有模块分节、没有那些"为什么这么写"的说明。

带注释的完整源码此前**只存在于本地工作区**。本地一丢、一清、一换机器，就再也 diff 不回去。
所以每个版本往这里推一份快照：**源码历史进版本库**，谁都能查"这一版到底怎么写的"。

## 命名与产出

- 文件名 = `CheatMenu-<版本>.lua`，**跟 `version.txt` 的版本号完全一致**。
- 由 `.workbuddy/build/push_docs.py` 自动推送（版本号取自 `build/VERSION`，**不写死**）。
- 本地源码文件名也遵循同一约定（发版后会自动改名为 `CheatMenu-<版本>.lua`，
  由 `push_now.py` 调用 `sync_src_name.py` 完成）—— 见仓库 `AGENTS.md` §5。

## ⚠ 一个必须知道的事

这份快照是**逐字节的源码副本**，所以源码里有什么，这里就有什么 ——
包括**硬编码的第三方 API key**（翻译模块的云端后端）。
该 key **在 minify 后的 `CheatMenu.lua` 里本来就已经是明文**，所以推快照**不会新增暴露面**；
但客观上它让 key 更容易被 grep 到 / 被抓取。

⇒ **建议**：如果这个 key 是限免/有额度上限的，请到服务商后台确认额度与告警；
需要换 key 时，改源码里的那一个常量即可（改完发一版，快照与产物都会同步）。
